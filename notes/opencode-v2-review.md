## Заменённые V1-контракты и аудит остатков

- Managed `serve` теперь использует поддерживаемый `--stdio` и JSON URL, фиксированный Basic username `opencode`/`OPENCODE_PASSWORD`; нет discovery пользовательского фонового сервиса и записи глобальных service settings.
- Старые health/provider/model/session message контракты заменены V2 `/api/info`, location-aware data wrappers, cursor pagination, flat model catalog и Model.Ref.
- Старые prompt/system/parts/model поля заменены inbox admission `/prompt`, instruction entry и `/model`; успешный HTTP admission не означает завершения turn.
- V1 parts/parentID/session.status events заменены V2 content/ordered ownership/idle outcome, `/session/active` и volatile event envelope. Корреляция основана на реальных session/input/assistant/tool/request ID.
- V1 MCP config/tool map/status ожидания заменены runtime `mcp.servers`, CodeMode=false, tombstones, exact effective catalog. Подключение без tools/list/каталога не считается готовностью.
- Native `bash`/`task` заменены `shell`/`subagent`; `write`/`patch` используют native action `edit`. Старые native todo/LSP/codesearch ожидания удалены из OpenCode mapping/policy.
- Старый question endpoint/positional answer заменён session-scoped permissions и forms с typed keyed answers.
- Связь с V1 `auth.json` удалена; выбран новый private native V2 store, без импорта старых сессий/bindings/config/credentials.
- Неоднозначная `OPENCODE_API_CONTRACT_VERSION = 2` удалена: это была ревизия Pioneer projection, не доказательство server V2. Сейчас fingerprint domain — `pioneer.opencode.server-v2`.

Поиск по adapter/MCP/plugin/instruction/reserved-args путям не нашёл старых `OpenCodeSystemPrompt`, `opencode_system_prompt`, `OPENCODE_API_CONTRACT_VERSION`, `prompt_async`, `message.part`, `session.status` events, `auth.json`, `/question`, строк native `"bash"`/`"task"`, legacy/fallback веток. Упоминание semver осталось только в имени регрессии, которая проверяет произвольную диагностическую версию. `OPENCODE_SERVER_PASSWORD` встречается только в списке удаляемых из child environment ключей, а не как authentication fallback. `session_status` — внутреннее имя метода, выполняющего V2 GET `/api/session/active`.

V1 fallback, compatibility layers, определение поколения API, отдельный провайдер V2, миграция/импорт экспериментальных данных и minimum/exact/semver gates не добавлены. Поддерживается только контракт V2. Нет ручного редактирования БД и очистки пользовательских данных.

## Конкретные ограничения и проверяемые риски

1. V2 credentials живут в native БД. Private Pioneer V2 store нужно отдельно авторизовать/настроить через V2 CLI либо допустимую provider configuration/environment. Readiness сообщает конкретные XDG/DB/config paths и команду `auth login --standalone`; она не выполнялась. Обычный пользовательский service/store не используется и credentials из V1 не копируются.
2. Native shell V2 объединяет stdout/stderr. Сохраняется `aggregatedOutput`, exit/signal/timeout/truncated; отдельные stdout/stderr передаются только при наличии в native metadata, искусственного разделения нет.
3. Native background jobs не поддерживаются. shell(background=true) получает типизированный отказ в Effect wrapper до вызова native executor; foreground shell и Pioneer task tools сохранены. Отказ проектируется как failed commandExecution и не считается запущенным background job; normal idle продолжает определять исход turn. Реальный V2 host/runner ещё требует проверки после разрешения. Native subagent запрещён.
4. Штатная websearch.provider поддерживается без tool metadata с реальными form/session/turn IDs и отсутствующим item ID. Произвольные plugin/global/чужие формы не присваиваются turn. Принадлежащие текущему turn формы неподдерживаемого типа (например external), hidden-only/required hidden без default явно отменяются с ошибкой. Native format/pattern validation может отклонить ответ; доставка ошибки завершает turn и закрывает owner.
5. SSE не имеет подтверждённого replay. После пропуска prefix дельты не домысливаются; полные ended/history восстанавливают результат. История/HTTP ответы ограничены существующим recovery budget; превышение явно завершает generation вместо тихой потери.
6. У V2 нет прежних native todo/LSP инструментов; их фиктивная проекция удалена. Доступный frozen набор инструментов Pioneer не расширяется ambient MCP.
7. Policy/catalog plugin требует официального V2 Effect/registry/RPC surface и host-provided modules. При отключённом plugin, отсутствующем shell или утрате wrapper catalog/readiness выдаёт ошибку; обхода изоляции нет. JS regression использует host double и не заменяет проверку на настоящем V2 runtime.
8. Возобновление native выполнения, прерванного смертью private owner, не обещается V2. Восстанавливается история сессии, собственные parked inputs отменяются; дальнейший recovery выполняет существующий Pioneer control turn, без повторной отправки уже принятого input.

Ни одна строка матрицы не означает подтверждённую работоспособность на бинарнике: проверены только исходные цепочки и соответствие опубликованному контракту.
