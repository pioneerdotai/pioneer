# Outbound tool contracts

The provider adapter owns the API contract; model catalog/discovery supplies model capabilities. `tools::policy` runs before inference in both chat paths. A caller's `parallel_tool_calls=true` permits multiple calls, while `false` requires at most one. An API without a verified control can omit `true` and retain native behavior, but must reject `false`. This is separate from the executor's concurrency.

Priority: explicit protocol prohibitions, then catalog model restrictions, then documented API defaults. Unknown is not a positive capability assertion. Protocol-wide `ProviderCapabilities.tool_calling` is a ceiling. `Provider::model_tool_calling` narrows it using the catalog; catalog absence does not prohibit custom/undiscovered models. `ModelCatalog::enrich` preserves discovery capability values and only supplies a known source value. Generated tool support stays in capability provenance alongside limits, from models.dev `tool_call`, OpenRouter `supported_parameters`, and Vercel `tags`. Old saved catalogs remain readable and leave missing support unknown.

There is no strict setting in `ToolDefinition`. Builders preserve the supplied schema, never silently opt into strict mode, and validate the root/name. Provider JSON Schema dialect acceptance is not certified by this check. In particular Gemini's Schema/JSON Schema representation needs the group 2 native structures work; strict is not inferred from a brand or from a structured-output flag.

History validation runs on the prepared outbound view, after existing provider/model history projection. Every outstanding call gets exactly one result before the next message/round, with matching name if supplied. Results can arrive in any order for ID-based protocols. IDs may repeat in distinct completed rounds but cannot repeat within a pending round. Arguments must decode to objects. Mistral's deterministic hash mapping and Bedrock's restricted-ID mapping apply to both sides and reject collisions. Native valid IDs are retained; persisted messages are not rewritten. Signed/provider replay requiring a changed ID fails pending replay-aware work in group 5. Ollama sorts only the serialized result view while retaining original message indexes for attachments.

This change does not alter usage extraction, accumulated history preparation, compaction, native casing, signed reasoning blocks, or stream assembly. It does not establish live acceptance, arbitrary schema support, or every installed local parser version. See the separate group 3 REPORT/COVERAGE for all 53 canonical providers, four reference comparisons, unexecuted regression cases and unresolved contracts.
