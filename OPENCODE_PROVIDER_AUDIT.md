### Статическая трассировка сценариев

- Другая patch/minor/major или custom release строка: `opencode_server_version` проверяет только healthy и возвращает строку metadata. Нет численного сравнения или проверки равенства release. Вызовы spawn из summary, probe и factory используют один код; normal turn, management, durable resume/fork и recovery приходят в тот же factory. Compaction использует тот же spawn через OpenCodeSummaryService.
- Отсутствующая, пустая либо не строковая version metadata: преобразуется в None, healthy API продолжает работу. `opencode_executable_fingerprints` кодирует None в base contract и пустую строку в прежнюю executable cache identity. Readiness и фактический startup используют одну нормализацию и реальные health metadata каждого процесса. Никакого semver parse для допуска OpenCode нет. Claude parsing служит только отображению; fallback сохраняет custom stdout, а None всё равно доходит до initialize и MCP attestation.
- Отсутствующий endpoint/несовместимый ответ: общий HTTP helper сохраняет endpoint label, HTTP status/invalid JSON/timeout; healthy!=true сообщает `/global/health did not report healthy=true`. `/provider`, tool IDs, session/MCP endpoints и SSE barriers остаются фактическими операциями. Claude/Codex initialize error сохраняется. Ни один из этих отказов не предлагает установить release X.
- Readiness → projection → startup: OpenCode readiness вычисляет fingerprint из реального executable + optional health version + внутреннего adapter contract. Frozen projection сохраняет этот fingerprint. Factory вычисляет его заново с version своего процесса и сравнивает только с этой projection, а не с эталонным release. Изменение binary/metadata делает прежнюю projection устаревшей; обычный refresh readiness и новая projection допускают обновлённый binary без изменения Pioneer.
- Binary identity не заменена version string: OpenCode каждый раз включает realpath/size/mtime/content SHA-256; Codex/Claude сохраняют прежнюю cheap cache identity и полную content attestation после cache miss. Проверки session/process generation, frozen callable/schema projection, private bridge attach/list/activation и отключение inherited MCP не ослаблялись. Нет перечня разрешённых binary hashes. Изменение metadata/бинарника инвалидирует прежнее свидетельство, а не запрещает новую release.
- Versions wire protocol, private bridge/receipts, overlay policy, database migrations и внутренний OPENCODE_API_CONTRACT_VERSION сохранены. Встроенные записанные decoder fixtures с release в имени описывают образец: установленная версия с ними не сравнивается.

## R2-01: согласованный snapshot и фаза dispatch

Статический статус: исправление внесено, требуется приёмка. Общий [reader](/Users/alexander/Code/pioneer/pioneer/.worktrees/opencode-provider/crates/gateway/src/cli_runtime/opencode_session.rs:4513) используется и в [authoritative snapshot](/Users/alexander/Code/pioneer/pioneer/.worktrees/opencode-provider/crates/gateway/src/cli_runtime/opencode_session.rs:3837), и в [SSE reconciliation](/Users/alexander/Code/pioneer/pioneer/.worktrees/opencode-provider/crates/gateway/src/cli_runtime/opencode_session.rs:4586). Он читает messages → status; если status idle, повторяет messages → status и разрешает terminal только при стабильной истории и повторном idle. Изменившийся набор сообщений означает InProgress и требует следующего наблюдения, а не failure.

Простая перестановка GET этим не подменяется: [local ownership/progress](/Users/alexander/Code/pioneer/pioneer/.worktrees/opencode-provider/crates/gateway/src/cli_runtime/opencode_session.rs:1287) отдельно защищает текущий подготовленный/отправленный prompt до подтверждения execution. User message сам по себе не считается входом в loop. Доказательство входа — текущий assistant/parent, busy после сохранённого current user либо соответствующие SSE user→busy/assistant events. [send_prompt](/Users/alexander/Code/pioneer/pioneer/.worktrees/opencode-provider/crates/gateway/src/cli_runtime/opencode_session.rs:4077) сохраняет prompt_async; HTTP 204 и canonical TurnStarted не очищают фазу awaiting_execution.

| Расписание | Разбор по текущему коду |
| --- | --- |
| Idle snapshot до начала отправки | begin_turn уже помечает local owned prompt ожидающим execution; deadline ещё отсутствует до send. Пустой snapshot не terminalizes ход. Ready barrier остаётся до HTTP. |
| User сохранён, busy ещё не установлен | Наличие user не снимает local phase. Даже два одинаковых REST user-only ответа с idle не дают ExecutionLost для этого prompt. При пришедшем busy/assistant phase снимается по evidence. Если M1 старее завершения, M2 изменяется и terminal откладывается. |
| Reconnect после фактического завершения/утраты | Для текущего observed loop стабильные messages и повторный idle дают final/abort/error/ExecutionLost по содержимому. Replacement runtime не владеет старым detached future: стабильный user-only idle там означает утраченное выполнение. Если у текущей generation так и не появился первый execution progress, существующий request_timeout задаёт dispatch deadline; после его истечения reader проверяет remote и local pending input, повторно проверяет progress/deadline под adapter mutex, **закрывает процесс**, затем однократно terminalizes с PromptStartupTimeout/сохранённой ошибкой. Это явная ограниченная отмена владельцем, а не вывод «idle значит future исчез». |

Pending permission/question перед входом loop не считаются потерей: remote endpoints и local pending state удерживают InProgress; успешный ответ возобновляет deadline. Deadline повторно проверяется после REST pending reads, чтобы старое истечение не отменило уже отвеченный запрос. Нет фиксированного sleep или отдельного watchdog/orchestrator; существующий liveness/recovery путь делает наблюдение. Уже наблюдаемый busy/tool/model loop не ограничивается этим startup deadline.

Stop до execution закрывает generation перед Interrupted; Stop deferred MCP prompt не отправляет его. Последующий activate не допускает terminal turn. `terminal_emitted` сохраняет однократность; delivery failure не перезаписывает уже установленный Interrupted. Cached history не подставляется вместо REST. При закрытии по startup deadline reader сохраняет проекцию только что прочитанных messages и отдельно передаёт доказанный control-plane terminal. Если generation уже закрыта к началу snapshot, адаптер требует reacquisition; существующий recovery acquisition вызывает manager.get_or_start_with_launch_spec и получает новый REST owner с той же managed DB. Отсутствие наблюдённого busy не объявляется доказательством отсутствия native items.

## R2-03: восстановленный prefix не блокирует дальнейший stream

Статический статус: исправление внесено, требуется приёмка. Вместо snapshot_items используется per-part native byte cursor в [delta mapper](/Users/alexander/Code/pioneer/pioneer/.worktrees/opencode-provider/crates/gateway/src/cli_runtime/opencode_session.rs:1762). REST и live part.updated проходят [общий part mapper](/Users/alexander/Code/pioneer/pioneer/.worktrees/opencode-provider/crates/gateway/src/cli_runtime/opencode_session.rs:1869); REST не сбрасывает native cursor. Накопленные SSE delta сравниваются только с покрытым участком snapshot; cursor продвигается даже когда событие уже покрыто. Часть delta за пределом prefix немедленно выдаётся как новый suffix. Permanent exclusion до begin_turn удалён.

Пример статического прохода для text и reasoning: native prefix `prefix ` → REST `prefix old ` → queued delta `old ` (покрыта, без append) → delta `new` (сразу опубликована) → final part.updated `prefix old new` (один ItemCompleted, без повторного delta). Новый part получает свой cursor и один ItemStarted. Full native baseline устанавливается даже у старого короткого initial part.updated, уже покрытого REST. Completed items отвергают поздние delta. Cursor не копирует весь накопленный текст на каждую delta.

В точном v1.4.14 [Session.updatePartDelta](https://github.com/anomalyco/opencode/blob/v1.4.14/packages/opencode/src/session/session.ts) публикует delta без записи каждого streaming suffix в DB; [processor](https://github.com/anomalyco/opencode/blob/v1.4.14/packages/opencode/src/session/processor.ts) сохраняет full text/reasoning через part.updated на start/end. Поэтому REST не является replay-журналом недоставленных transient delta. При разрыве будущие delta продолжают публиковаться; definitive full completion исправляет недоступный в REST промежуток и plugin replacement. Сопоставление произвольных повторяющихся строк по эвристическому overlap не добавлено. Reasoning completion теперь заполняет content, который потребляет shared projector, а сокращённый final text имеет приоритет над старым prefix.

Fixture `restored_prefix_deduplicates_queued_deltas_then_resumes_text_and_reasoning` включает обе разновидности частей, queued/new suffix, final, late delta, следующий part и final shortening. Он **не выполнялся**.
